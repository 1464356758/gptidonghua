# 小说自动接力系统
# 整合说明书与操作教程

版本：安卓匹配生成器 1.0.0-RC2 / 电脑控制台 0.2.0 / AUTO-0.2.0-RC2

适用：安卓手机生成匹配包，Windows 电脑上的 Chrome 或 Edge 负责普通聊天自动接力。沿用你提供的 333 十角色工作流，每章三个写手竞争、两个审核员独立审核。

本册先带你跑通一本验收样书，再开三本。APP 负责生成配置和角色规则；小说正文由你账号里的角色聊天创作、写入 GitHub。安装 APP 本身不会开始写作，也不会修改 GitHub。

## 01｜先弄清整套系统由什么组成

| 部件 | 做什么 | 在哪里使用 |
| --- | --- | --- |
| 小说匹配生成器 APP | 填参数，生成、保存、分享匹配 ZIP；保留三本配置草稿 | 安卓手机 |
| 小说接力控制台 | 发送角色任务、检测完成、排队、暂停和恢复 | 电脑 Chrome / Edge 扩展 |
| GitHub 控制仓库 | 存控制台源码和运行调度记录 | 1464356758/gptidonghua |
| 每本小说的仓库 | 存该书规则、任务、正文、审核、定稿和完成凭证 | 一本一个仓库，三本三个 |
| 学堂仓库 | 存四个平台的规则、活动、资料与角色调用入口 | 默认 1464356758/xueyuan，可改 |
| 十个角色聊天 | 按各自职责执行任务并提交产物 | 一本十个，三本三十个 |

两个固定地址：

- 控制仓库：https://github.com/1464356758/gptidonghua
- 默认学堂：https://github.com/1464356758/xueyuan

小说仓库由你另外新建，例如 book01、book02、book03；这些只是命名示例，系统不会替你创建同名仓库。小说仓库、学堂仓库和控制仓库不要混用。

你仍然决定最终选题、处理登录和额度恢复、核对不能自动判定的异常。正常角色交接由控制台完成，不需要再把上一位 AI 的长回答复制到下一位。

## 02｜第一次使用，按这条顺序走

1. 在 GitHub 创建一本验收样书仓库，勾选添加 README，确保有 main 分支。
2. 手机安装本包 APK，填写这本书和学堂参数，生成并保存 ZIP。
3. 把 ZIP 发到电脑；在电脑安装本包的新版 extension 扩展。
4. 连接控制仓库，导入手机 ZIP，检查学堂，初始化样书空仓库。
5. 等小说仓库五套 CI 检查通过，建立并绑定十个普通聊天。
6. 登记小说，点击“开始 / 继续接力”；灵感裁判完成后，由你选择题材。
7. 观察第一章三稿、双审核、总监锁定以及第二章是否自动开始。
8. 样书验收后，再用同样步骤登记另外两本正式项目。

验收样书建议只设 1 至 2 章；正式书仍可用 1 至 100 章、每章 8000 至 10000 字。字数范围会实际传给写手和检查器；不要把随便填写的小字数测试参数带到正式百章书里。

开始前确认两种 GitHub 能力：控制台令牌能够访问仓库；普通聊天里的 GitHub 连接也确实能够读取、写入。两者独立，给扩展填令牌不会让模型自动获得 GitHub 写权限。

## 03｜安装安卓 APP 和填写每个字段

在手机打开“小说匹配生成器_Android_1.0.0_RC2.apk”。如系统提示，给当前文件管理器或浏览器开启“允许安装此来源的应用”，完成后可关闭该权限。本 APP 与旧 V4.3.2 使用不同应用标识，可以同时保留。旧 APP 中的配置不会自动搬过来。

最低 Android 8.0；需要较新的 Android System WebView。生成操作可以离线完成。APP 不需要 GitHub 令牌、ChatGPT 密码、通讯录、照片或所有文件访问权限。

| 字段 | 示例 / 默认值 | 应该怎么填 |
| --- | --- | --- |
| 独立书号 | book01 | 英文、数字、下划线或连字符；每本不同 |
| 项目名 | 第一部小说 | 便于识别的名字，可以用中文 |
| 小说平台 | 番茄小说 | 番茄、七猫、起点、豆瓣阅读四选一 |
| 小说仓库根链接 | https://github.com/你的用户名/小说仓库 | 不填某个文件、issues 或网页分享地址 |
| 小说仓库分支 | main | 必须和 GitHub 中实际使用的分支一致 |
| 学堂仓库根链接 | https://github.com/1464356758/xueyuan | 地址变化时直接修改；也可填 owner/repo |
| 学堂仓库分支 | main | 与小说分支相互独立；可填其他已有分支 |
| 起始章 / 最后章 | 1 / 100 | 正整数，最后章不能小于起始章 |
| 每章最少 / 最多字数 | 8000 / 10000 | 正整数，最多不能小于最少 |
| 灵感关键词 | 县城、旧车站、悬疑 | 可不填；最终题材仍由你选择 |

豆瓣在这里指“豆瓣阅读”，不是豆瓣社区。选择哪个平台，角色就按该平台的学堂入口取资料，不把四个平台规则混在一起。

APP 顶部“小说一 / 小说二 / 小说三”是三份本机表单草稿。切换时保留各自内容，不代表电脑已经登记这本小说。卸载 APP 或清除应用数据可能丢失草稿，请保留生成的 ZIP。

## 04｜生成、保存、分享匹配包

填好后点击“生成并保存 ZIP”。APP 完成生成后，打开安卓系统的文件保存界面；选 Downloads 或你认识的文件夹，点保存。只有出现“ZIP 已保存”才说明已完成系统保存。

点“生成并分享 ZIP”会按当前表单重新生成一份包，然后打开系统分享菜单。选择你平时传文件到电脑的方式；取消分享不会修改 GitHub。ZIP 文件本身包含完整内容，不依赖聊天中那一行提示文字。

文件名示例：book01_小说匹配文件_AUTO_RC2.zip。每本书保留各自的 ZIP，最好另备份一个带日期的副本。该 ZIP 内有正文工作流、十角色指令、五套 CI、自动化协议、项目配置和文件哈希清单。

匹配包中的“自动化/控制台导入.json”供电脑快速填表。直接导入 APP 原始 ZIP 最方便；如果 ZIP 被其他软件重新压缩导致不能导入，可先解压，再导入该 JSON。导入不会运行包内程序，不会导入令牌、聊天地址或远端运行状态。

离线备用：完整交付包另附“portable/手机匹配文件生成器.html”。电脑用 Chrome 或 Edge 打开即可生成同样的包。手机的普通文件预览器可能不运行脚本；安卓手机优先使用 APK。

## 05｜电脑安装扩展和连接 GitHub

1. 把完整交付包解压到固定文件夹，例如“文档/小说自动接力”。不要在运行时移动或删除它。
2. Chrome 地址栏输入 chrome://extensions/；Edge 输入 edge://extensions/。
3. 打开“开发者模式”，选择“加载已解压的扩展程序”。
4. 选择 extension 文件夹，也就是能看见 manifest.json 的那一层。
5. 在工具栏打开“小说接力控制台”。新版本号应为 0.2.0。

已经装过 RC1 的情况：先暂停旧控制台，等待在途任务结束。保留原扩展所在文件夹，用新版 extension 文件更新其内容，然后在扩展页点“重新加载”。不要安装第二个扩展并同时控制同一批书。已有角色绑定保存在原浏览器本机；移除扩展再安装可能丢失这些本机数据。

在 GitHub 头像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens 创建令牌。只授权控制仓库、本次小说仓库；如学堂是私有仓库，也要授权学堂。

| 权限 | 用途 |
| --- | --- |
| Contents：Read and write | 保存控制状态、任务、匹配文件；读取学堂 |
| Actions：Read-only | 检查小说仓库的五套 CI 结果 |
| Workflows：Read and write | 首次初始化需要创建五个工作流文件；初始化后可换成较小权限的运行令牌 |
| Metadata：Read-only | GitHub 默认要求的仓库元数据读取 |

在控制台“① 连接控制仓库”填写 1464356758/gptidonghua、main 和令牌，然后点“连接 GitHub”。令牌只保留在本次浏览器会话，关闭浏览器后需要重新填写。不要把令牌发到 AI 对话、ZIP 或仓库。

## 06｜导入 APP 配置并初始化新书

展开控制台“② 生成匹配文件 / 登记一本小说”。在“导入手机 APP 匹配包或配置 JSON”选择刚才的 ZIP，表单会自动填入书号、平台、小说仓库、两种分支、学堂和创作范围。

导入会清空表单内的十角色地址，防止上一部小说的聊天被误用于这一本；已登记小说的实际绑定不会因此被修改。先逐项核对，然后点“检查学堂连接”。此操作检查指定分支的“学院入口.json”“自动选题入口.json”和所选平台的入口，成功时显示学堂提交号。

连接检查通过只说明入口可读、目录兼容，不代表全部资料都新鲜、没有缺页。正式创作时，角色还必须读取资料、检查活动有效期，并冻结所采用的规则快照。

接着点“初始化这本小说的空仓库”。系统一次性写入匹配文件，回读配置；只允许目标仓库为空或只有 README。它不会创建仓库，也不会覆盖已经存在的小说系统。

打开小说仓库的 Actions 页面，等待以下五项成功：

- Novel System CI
- Novel Contract CI
- Writer Scoreboard CI
- Stage Integrity CI
- Strict Stage Gate CI

这五项在初始化阶段通过，表示空项目结构合格，不表示小说已创作完。后续总监关键产物也会检查对应提交的 CI。

## 07｜建立十角色普通聊天

每本书单独建立十个普通聊天，选择你账号实际可用的模型，并确认 GitHub 连接可用。每个聊天可先发送：“这是 book01 的某某角色对话，等待正式任务，不开始创作。”如按旧方式初始化角色，可使用本书匹配包内同名角色指令。

| 角色编号 | 职责 | 聊天命名示例 |
| --- | --- | --- |
| 01 灵感员 | 根据关键词与所选学堂资料提出候选 | book01_01灵感员 |
| 02 灵感裁判 | 评估候选，给出可选名单 | book01_02灵感裁判 |
| 03 总监 | 立项、任务、匿名交接、返修、记忆与锁定 | book01_03总监 |
| 04 写手 A | 独立候选稿及自己的返修 | book01_04写手A |
| 05 写手 B | 独立候选稿及自己的返修 | book01_05写手B |
| 06 写手 C | 独立候选稿及自己的返修 | book01_06写手C |
| 07 章节裁判 | 按匿名材料评选章节候选 | book01_07章节裁判 |
| 08 逻辑审核员 | 因果、动机、设定和连续性 | book01_08逻辑审核 |
| 09 中文文风审核员 | 中文自然度、翻译腔、模板化表达 | book01_09文风审核 |
| 10 阶段总审员 | 阶段与全书连贯性、回修核查 | book01_10阶段总审 |

把十个聊天的完整地址分别填到控制台。地址形如 https://chatgpt.com/c/对话编号；不能填首页、分享链接或项目首页。每个角色只开一个对应标签页；同一对话打开两份会导致发送不明确。

确认同一本书十个地址不同、不同书也不复用对话，然后点“登记这本小说”。只导入 ZIP 不算登记；登记前也不会自动发送写作任务。

运行期间不要手动往已绑定角色发新的创作任务。需要讨论问题时另开聊天，以免与自动任务混在一起。

## 08｜从选题到章节锁定怎么流转

点击“开始 / 继续接力”。初次需要打开角色页面，通常在下一轮检查继续发送；控制台约每分钟核对 GitHub。暂时没变化时先看“最近同步”和提示，不要重复手动发送同一任务。

第一段：灵感员提出候选 → 灵感裁判评估 → 控制台停在“等待用户选题”。打开完整报告，选择一个可选候选，点击“我选择这个题材”。最终决定仍然在你手中。

第二段：总监读取交接，建立正式设定和任务。三个写手整组排队，独立生成候选正文，分别写进本书 GitHub。全部交出有效完成凭证后，总监整理匿名评审材料，交章节裁判。

第三段：裁判提交结果，总监确认交接；逻辑和文风两个审核员整组执行，读取同一获选版本。两位都完成后，总监才作出锁定或返修决定。

返修：总监发具体修改令，交原获选写手；完成后再次进行规定的裁判复核和双审核，回到总监。每章最多三轮返修；超过上限会停下，不能靠无限重试掩盖问题。

锁定（LOCK）表示通过该轮规定审核后，把具体正文版本和校验信息固定下来。它不等于“文字完美”，也不等于已经发布到小说平台。锁定后总监安排下一章，下一章仍是三个写手竞争。

阶段节点由原工作流规则和总监任务决定；阶段总审完成后，可能继续写、回修指定章节或进入全书总审。最后全书通过后标记完成，不会自动登录平台发布小说。

## 09｜三本小说与六个执行席位

每本书有自己的仓库和十个聊天。控制台统一管理最多三本书、六个在途执行席位。这是系统排队限制，不是对 ChatGPT 服务器实际同时思考数量的测量。

| 当前情况 | 调度行为 |
| --- | --- |
| 两本书都等三个写手 | 两组可共占六席 |
| 第三本也等三个写手 | 等有三个可用席位再启动整组 |
| 当前只空两个席位 | 可以安排一组双审核，不拆开三写手组 |
| 写手 A、B 完成，C 未交有效凭证 | 该书不能进入下一轮裁判 |
| 审核员一人完成，另一人未完成 | 该书不能进入总监审核裁决 |
| 一书配置错误 | 阻断该书；其他正常项目仍可推进 |
| 账号限额、登录或验证码 | 全局暂停新发送，等你处理 |

“整组启动”表示先为整个小组预留席位，再依次点击发送；浏览器操作会相差几秒，并不是同一毫秒启动。各角色后台执行可以重叠，下一关仍等待整组凭证。

GitHub 的有效完成凭证用于推进业务；席位要等网页被连续观察为空闲后才释放。网页卡住但 GitHub 已交付时可以准备下一步，但旧任务未确认空闲前仍占席位，防止超过六席。

## 10｜为什么创建了文件还不算完成

一个任务至少涉及三类记录：任务文件、结果索引、最终完成凭证。最后的完成凭证必须绑定本任务身份、输入快照、产物固定提交和文件哈希；没有通过这些核验，不能只凭“正文.txt 已出现”就进入下一步。

| 记录 | GitHub 路径 |
| --- | --- |
| 本轮任务 | 自动化/任务/任务编号.json |
| 结果索引 | 自动化/结果/任务编号.json |
| 最后完成凭证 | 自动化/完成/任务编号.json |
| 项目参数 | 自动化/项目配置.json |
| 电脑快速导入参数 | 自动化/控制台导入.json |
| 全局调度记录 | 控制仓库中的 自动化控制/控制台.json |

角色必须把完成凭证作为本轮最后一次业务写入，之后网页只回复任务编号、完成或阻断、GitHub 路径。正文与完整审核报告都在 GitHub，控制台不需要等待网页长回答渲染完。

如果 GitHub 已验完而网页仍忙，系统会保留席位并等待；持续卡住达到条件后最多刷新一次显示。刷新不是取消任务，也不是允许重发任务。

发送前先保存记录。若浏览器在点击前后崩溃，系统可能不能确定消息有没有真正发出，会显示 UNCERTAIN（发送情况不明）；它不会自动再发一次。

## 11｜日常开始、暂停、恢复与看进度

每天开始：打开电脑和原浏览器 → 打开控制台 → 重新填令牌连接 → 点击“立即核对 GitHub” → 查看阻断和在途任务 → 点击“开始 / 继续接力”。

暂停时点击“暂停新任务”。已经发送的角色会继续执行，控制台仍核对完成记录；暂停不会撤回消息或强行停止模型。准备关机时，尽量让在途任务完成后再关。

| 状态或提示 | 你该做什么 |
| --- | --- |
| 等待用户选题 | 阅读灵感裁判报告，选择题材 |
| 等待整组空闲 / 等待席位 | 查看其他任务是否仍在执行，正常等待 |
| SENT | 已确认发送，等待 GitHub 有效完成凭证 |
| ACCEPTED | 凭证已验；网页未确认空闲时仍可能占席位 |
| UNCERTAIN | 核对原聊天历史和 GitHub；确认确实没发送后才用专用重试按钮 |
| 任务超过两小时 | 查看原角色、GitHub 和网络，不能手动清空席位 |
| CI 待完成 | 到该小说 Actions 页查看对应提交，等待或处理失败原因 |
| BLOCKED / 该书阻断 | 按提示解决问题，再点“已处理，重新核验” |
| 全书完成 | 去定稿目录核对交付内容，后续发布另外处理 |

电脑需保持运行、联网，浏览器不能关闭或进入系统睡眠。断网、睡眠、关机不代表进度消失；恢复后先核对，不要重新初始化仓库。

## 12｜学堂地址失效以后怎么换

先区分：网址写错、仓库改名、分支不存在、私有仓库没权限、学堂文件缺失、整个账号不可用。404 也可能表示无权访问，不能一看到 404 就删资料重建。

对还没开始的新书：把学堂资料完整放到可访问的新仓库 → 在 APP 填新根链接和学堂分支 → 重新生成 ZIP → 导入新版控制台 → 点“检查学堂连接” → 按新书步骤初始化。其他参数不用逐个到包内手改。

新学堂至少保留“学院入口.json”“自动选题入口.json”，以及“平台/番茄小说/入口.json”“平台/七猫小说/入口.json”“平台/起点中文网/入口.json”“平台/豆瓣阅读/入口.json”和其中引用的实际资料。只建立一个同名空仓库不会恢复学堂。

对已经写作的小说：先暂停新任务，等在途任务核对完；备份小说和学堂的完整仓库。不要点“初始化这本小说的空仓库”，不要把新生成包整体覆盖进去。已有书可能绑定了旧学堂的冻结提交 SHA；新地址即使文件看起来一样，也未必拥有同一个历史提交。

本版提供新包换链接和一致性检查，没有“已有书一键迁移学堂”按钮。已有书需要总监先做迁移核对：旧冻结提交在新仓库是否可读、引用文件与哈希是否一致、规则内容是否有变化；再受控更新小说配置、角色指令和控制仓库中该书配置。无法回读旧快照时先阻断，不可用“已改网址”替代验证。你可以把下面的话发给本书总监发起核对：

> 本书需要迁移学堂。旧地址：[旧学堂]；新地址：[新学堂]；新学堂分支：[分支]。当前已暂停新任务。请先读取本书真实运行状态、数据库入口、平台规则冻结快照与在途任务，列出迁移影响和可回读证据；不得覆盖正文、旧审核、LOCK 或运行状态，不得直接宣布迁移完成。需要同步小说配置与控制台已登记配置，所有引用一致并回读后才能恢复。

预防资料丢失：定期下载学堂文件备份；需要保留冻结提交时还应保存完整 Git 历史。只下载网页 ZIP 保存的是当时文件，不包含完整提交历史。

## 13｜常见问题，按现象处理

| 现象 | 处理方法 |
| --- | --- |
| APP 点击生成没成功 | 先看底部错误，检查仓库根地址、书号和数值；必要时更新系统 WebView |
| 安装时提示与旧 APP 不兼容 | 核对是否下载了本册对应的新 APK；它应与旧 V4.3.2 独立安装 |
| 保存后找不到 ZIP | 回想系统保存界面选的位置；可重新生成并分享，不要反复改项目参数 |
| 导入 ZIP 报重新压缩 | 解压后选“自动化/控制台导入.json”；不要导入整个系统交付包 |
| 学堂检查报不兼容 | 核对分支及入口目录，确保不是只有空仓库或不同结构的资料包 |
| 初始化被拒绝 | 目标仓库已有其他文件；确认选对新书仓库，不要删除已有小说来强行通过 |
| 403 / 401 | 检查令牌权限、有效期和仓库授权；聊天 GitHub 连接也要单独检查 |
| 有正文，仍没有下一步 | 检查完成凭证、固定提交、哈希及 CI；正文存在本身不算完成 |
| ChatGPT 回答很长或显示卡顿 | 先看 GitHub 完成记录与控制台，不要因此重复发送任务 |
| 会员提示稍后再试 | 按服务方提示等待恢复，恢复后核对再继续；六席不会增加会员额度 |
| 更换电脑后找不到角色 | 原机器先暂停并结束在途任务；新电脑重新绑定原十个聊天 |
| 选题或写作不满意 | 正常走总监修改或重选流程，自动化只负责交接，不替你保证文学质量 |

如果界面选择器随 ChatGPT 网页更新失效，控制台会保持未知状态或暂停；需要更新扩展适配，不应手动绕开完成验证。

## 14｜第一次验收与今后备份

第一本样书至少核对以下项目：

1. 手机修改学堂地址或分支后，生成包与电脑导入表单完全一致。
2. 每个角色能真实读写本书 GitHub，不用人工转传正文。
3. 最后一位写手完成之前，不提前进入下一关。
4. 双审核都完成后，总监才决定锁定或返修。
5. 返修交回原获选写手，修改后有新的审核记录。
6. 一章通过后，第二章仍按三写手竞争继续。
7. 暂停后不发送新任务，恢复时不重复发送已经收到的任务。
8. 三书开启后，控制台占用席位总数不超过六。

以上真实账号验收完成前，不把候选版当成已经验证过的长期无人值守成品。自动测试、浏览器模拟和安卓模拟器验证会单独记录在交付包中；它们不能替代你账号的完整写作测试。

建议保留：本次完整交付包、每本书的原始匹配 ZIP、小说仓库备份、学堂文件及历史备份、你自己的十角色地址记录。令牌单独保管，别放进公开仓库或共享文档。
