# 第一次怎么操作

不需要安装Python或Node；它们只用于开发测试。运行端是Windows电脑的Chrome/Edge。不要把ZIP直接当安卓APK安装。

## 1. 安装扩展

1. 解压完整交付ZIP到一个固定文件夹，不要运行中删除或移动。
2. Chrome地址栏输入 `chrome://extensions/`，Edge输入 `edge://extensions/`。
3. 开启“开发者模式”，点击“加载已解压的扩展程序”。
4. 选择包里的 `extension` 文件夹，能看见 `manifest.json` 的那一层。
5. 在扩展列表找到“小说接力控制台”，固定到工具栏，点击图标打开控制台。

本版不是应用商店签名安装包，浏览器可能显示开发者模式提示。无需粘贴代码到控制台，无需安装任何第三方挂机程序。

## 2. 准备GitHub权限

控制仓库已经指定：`1464356758/gptidonghua`，main。

每本小说单独创建一个仓库。创建时勾选初始化README，确保存在main分支；暂不添加其他代码。可以选择私有仓库。若不想别人看到小说内容，不要把小说仓库建为公开。

在GitHub头像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens中创建令牌：

- Repository access：只选控制仓库和本次要用的小说仓库；如需要读取私有学院，也选学院。
- Contents：Read and write，用于控制状态、任务及初始化文件。
- Actions：Read-only，用于读取五套CI结果。
- Workflows：Read and write，仅因首次初始化包含 `.github/workflows/`。完成初始化后可以改用不含Workflows写权限的运行令牌。
- Metadata：保留GitHub要求的读取权限。

把令牌粘贴到扩展“连接控制仓库”中，不要发到聊天里。浏览器关闭后令牌清除，重新开机需要再填一次。令牌被撤销或过期时程序会停止发送，已有进度不会删除。

**还需要另外检查ChatGPT中的GitHub连接。** 扩展令牌不能让聊天模型自动获得GitHub写权限。每个角色要使用能够真正读取和写入指定仓库的现有GitHub连接；如果只能搜索不能写，自动化不能凭空补出权限。

## 3. 先建一本短样书

在“生成匹配文件 / 登记一本小说”填写：

- 书号：`book01`，项目名自定。
- 平台：四选一。
- 小说仓库：刚建立的独立仓库根地址。
- 分支：main，或自己已经存在的分支。
- 起始章、最后章、字数：先用自己的验收样书范围，例如1—2章；不要误把验收样书和正式百章仓库混在一起。
- 灵感关键词：本书想写的方向。

点击“初始化这本小说的空仓库”。控制台会生成匹配文件、一次性提交并回读关键配置。它只允许初始化空仓库或只有README的仓库，遇到已有小说系统会拒绝覆盖。

到小说仓库的Actions页看原五套CI是否成功。首次生成的是空项目结构检查通过，不等于小说已经写好或全流程已经验收。

“生成匹配ZIP”和“分享匹配ZIP”保留，供备份或按旧方式交总监初始化。直接初始化已成功时，不必再上传同一个ZIP。

手机配置：用浏览器打开完整包内 `手机匹配文件生成器.html`，填写同样参数生成ZIP。若系统文件预览器不执行脚本，改用浏览器打开；分享不可用时会改为下载。这个HTML不是修改后的原APK，后台接力仍需电脑扩展。

## 4. 绑定十个普通聊天

每本书十个独立聊天，按下面顺序命名：

| 控制台角色 | 建议聊天名 |
| --- | --- |
| 灵感员 | book01_01灵感员 |
| 灵感裁判 | book01_02灵感裁判 |
| 总监 | book01_03总监 |
| 写手A | book01_04写手A |
| 写手B | book01_05写手B |
| 写手C | book01_06写手C |
| 章节裁判 | book01_07章节裁判 |
| 逻辑审核员 | book01_08逻辑审核 |
| 中文文风审核员 | book01_09文风审核 |
| 阶段总审员 | book01_10阶段总审 |

先手动创建普通聊天并选择你账号实际可用的模型。用一句“这是book01的XX角色对话，等待正式任务，不开始创作”建立对话。按你原有连接方式确保GitHub可用。控制台每轮会发送自包含任务定位，角色仍要真实读取仓库里的角色规则；不用人工搬运上一个角色全文。

把各聊天的完整地址 `https://chatgpt.com/c/...` 分别填入控制台。不能填首页、分享页或项目首页。一个对话只保留一个标签页，避免同一角色重复页面导致发送歧义。之后点“登记这本小说”。

角色链接只存本机。换电脑必须先让原电脑所有在途任务结束、暂停，再迁移或重绑定；本版本不会在仍有旧任务时强行抢占执行。

## 5. 第一次开始

点击“开始 / 继续接力”。首次可能要等页面加载及下一次一分钟检查。灵感员完成后进入灵感裁判，之后停在“等待用户选题”。查看完整报告，在控制台选择一个候选并点击“我选择这个题材”。

从这个节点开始，任务经GitHub自动接续。你只需观察：

1. 总监发布正式任务后，三写手是否均发送，席位数是否正确。
2. 最后一位写手交有效凭证之前，总监不得进行匿名/评审。
3. 双审核都完成后，总监才决定LOCK或返修。
4. 总监产物提交的五套CI是否全部成功。
5. 一章锁定后，下一章是否仍然三稿竞争。

如果出现暂停或阻断，按故障说明处理，不能点击“重试”来替代核对。系统不会因为你连续点击继续就略过SHA或CI。

## 6. 验收通过以后登记另外两本

同样填写book02/book03、各自小说仓库与各自十个聊天。不得复用book01的对话。三本同时排队时，两组三写手可以占满六席，第三组等待。两个审核空位不能用来拆开第三组三写手。

不要在控制台运行时手动往绑定角色发新任务。不要同时开两个控制台控制同一套项目。不要让电脑自动睡眠；断网、睡眠或关闭浏览器会暂停接力，并保留已登记状态。

## 7. 每次重启

打开浏览器和扩展 → 重新填令牌连接 → 打开需要恢复的原角色对话 → 点击立即核对GitHub → 查看是否有UNCERTAIN或阻断 → 确认状态后继续。尚未验凭证的任务不能按“看起来结束了”手动清零。

最终选题、登录/验证码、会员限额恢复和无法自动判断的故障仍由你处理。日常无异常交接由控制台代替复制粘贴。
