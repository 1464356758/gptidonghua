# 遇到问题时怎么处理

| 看到的现象 | 系统处理 | 用户操作 |
| --- | --- | --- |
| 文件已有，但一直等待 | 没有合法完成凭证，不推进 | 查看角色是否仍在执行；完成后检查自动化/完成对应job文件 |
| 额度、登录、验证码提示 | 全局暂停新发送，席位保留 | 在原网页按提示恢复；额度以服务方显示时间为准，再点继续 |
| 网页答案没显示完整 | GitHub凭证仍可核对业务完成 | 不需要复制正文；凭证已验但网页持续忙时扩展最多刷新一次 |
| UNKNOWN / 等待整组页面 | 找不到已知控件或页面尚未加载 | 打开原对话、等待加载；保留一个标签页；若页面改版，停用发送并更新适配代码 |
| COMPOSER_DIRTY | 不覆盖输入框中用户文字 | 用户确认草稿用途后自行处理，再继续 |
| UNCERTAIN | 不确定点击是否成功，不自动重发 | 检查完整原聊天历史是否出现任务号，先看GitHub凭证；只有明确没发过才点核对后重试并输入确认句 |
| 固定产物SHA不符 | 本书阻断 | 检查该固定提交和被改文件；修正错误交付或凭证后重新核验，保留Git历史 |
| 等待五套CI | 只等指定artifact_commit，不信模型自报 | 到对应小说仓库Actions检查该SHA，不要拿另一个提交的绿灯冒充 |
| CI失败 | 本书不进入下一阶段 | 看具体失败日志，修正正式文件；对新产物提交重新建立有效完成凭证 |
| GitHub401 | 身份无效 | 重新创建/填写令牌；不要把令牌发给角色 |
| GitHub403/429 | 权限不足或请求限额 | 先看令牌权限或服务端重置时间，等待后再同步；不要不停点击 |
| 另一控制台正在执行 | 拒绝第二实例抢占 | 回到原电脑继续；让在途任务结束且暂停后再迁移 |
| 标签页关闭、电脑休眠 | 不据此释放在途席位 | 打开原对话，恢复网络，重新核对GitHub |
| 第三轮仍有重要问题 | 总监HOLD | 由用户和总监决定调整方向；不要自动无限返修 |

普通SHA、格式或CI错误只让本书暂停。点击“已处理，重新核验”只重新检查，不会跳过门禁，也不会自动重写正文。

阻断修复涉及完成凭证时，先暂停新发送，确认原任务已结束。应修正真正缺失的文件、哈希或引用，留下GitHub新提交；不得把`pass=false`直接改成`true`，不得编造字数或CI结果。模型需要重新思考正文时，应由总监建立正式新版本和返修令，不能用更改旧凭证掩盖重新执行。

本版本没有“强制清空全部任务”和“无条件抢占控制台”按钮。这些操作会让仍在运行的模型被漏计、导致重复任务。若本机绑定或状态丢失且仍有在途任务，先保留仓库现状，交开发者根据固定job、提交和原对话核对恢复，不直接重置控制台JSON。

人工介入期间不要在模型仍思考时同时改它正在写的同一个文件。源代码修复应在停止新发送、确认影响范围后部署，不自动从仓库下载并执行任意更新脚本。
